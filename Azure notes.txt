Triggers in Azure data factory:
Triggers - you can execute your pipeline
Triggers determine when a pipeline execution needs to be kicked off.
Pipelines and triggers have many-to-many relationships(except for the tumbling window trigger).
Multiple triggers can kick off  a single pipeline, or a single trigger can kick of multiple pipelines.
Types of Triggers in Azure Data factory:
1. Schedule Trigger - A trigger that invokes a pipeline on a wall clock schedule
2. Tumbling window Trigger - A trigger that operates on a periodic interval, while also retaining state.
3. Event based trigger - A trigger that responds to an event.
Schedule trigger runs pipeline on a wall clock schedule. This trigger supports periodic and advanced calendar options.
Tumbling Window Trigger in Azure Data Factory:
Tumbling window triggers are a type of trigger that fires at a periodic time interval from a specified start date, while retaining state.
It has one-to-one relationship with a pipeline.
Difference between Tumbling window and Schedule window:
A Schedule Trigger runs according to a schedule but a tumbling window trigger processes continuous, fixed-size, non overlapping time windows and maintains state for each state.

Mapping data flow:
Mapping data flows are designed data transformations in Azure Data Factory. Data flows allow data engineers to develop graphical data transformation logic without writing code.
Data flows are executed as activities within Azure Data factory pipelines using Data Flow Activities.
ADF internally handles all the code translation, spark optimization and execution of transformation.
Mapping data flow debug mode in Azure Data Factory:
Azure Data Factory mapping data flow's debug mode allows you to interactively watch the data shape transform while you build and debug your data flows.

Filter Transformation in Mapping Dataflows:
Filter transforms allows row filtering based upon a condition. The output stream includes all rows that matching the filtering condition. The filter transformation is similar to a where clause in sql.
Aggregate Transformation in Mapping Dataflows:
Aggregate transformation defines aggregations of columns in your data stream. Using the Expression Builder, you can define different types of aggregations such as SUM, MIN, MAX and Count grouped by existing or computed columns.
Exists Transformation in sql:
Exists transformation is a row filtering transformation that checks whether your data exists in another source or stream. The output stream includes all rows in the left stream that either exist or don't exist in the right stream. The exists transformation is similar to SQL WHERE EXISTS and SQL WHERE NOT EXISTS.
Union Transformation in ADF:
Union will combine multiple data streams into one, with the Sql union of those streams as the new output from the Union Transformation.
Lookup Transformation in ADF:
A Lookup Transformation is similar to a left outer join. All rows from the primary stream will exist in the output stream with the additional columns from the lookup stream.
Sort Transformation in ADF:
The Sort Transformation allows you to sort the incoming rows on the current data stream.
New Branch in DataFlow:

Pivot Transformation in Mapping Data Flow:
Use the Pivot Transformation to create multiple columns from the unique row value of a single column.
Un Pivot Transformation in Mapping Data Flow:
Use Unpivot in ADF Mapping data flow as a way to turn an unnormalized dataset into a more normalized version by expanding values from multiple columns in a single record into multiple records with the same values in a single column.
Surrogate Key in Azure Data Factory:

Window Transformation in Mapping Data Flow in ADF:

A new field will be generated in your output that includes these aggregations.

Different Author Modes in Azure Data Factory:
By default, the Azure Data Factory authors directly against the data factory service. This will have below limitations.
1. ADF service doesn't include a code repository. Hence ADF Components will be directly published to Data factory service and we cannot perform Partial Saves and we cannot save JSON code for ADF and its components
2. ADF service is not optimized for collaboration and version control.
Hence, to provide better Authoring Experience ADF allows you to configure a git repository with either Azure repos or GitHub.
Advantages of Git Integration:
1. Version Control.
2. Partial Saves.
3. Collaboration and control.
4. Better CI/CD.
5. Better Performance.
Version Control
1. Ability to track/audit changes.
2. Ability to revert changes that introduced bugs.
Partial Saves:
1. When authoring against the data factory service, you can't save changes as a draft and all publishes must pass data factory validation.
Collaboration and control
1. If you have multiple team members contributing to the same factory, you may want to let your teammates collaborate with each other via a code review process.
Better CI/CD:
Better Performance:
An average factory with git integration loads 10 times faster than one authoring against the data factory service.
